<task type="auto">
  <name>Task 1: Implement Exponential Backoff Retry Loop and Dead-Letter Parking in run_tick()</name>
  <files>backend/server.py</files>
  <read_first>backend/server.py</read_first>
  <action>
    Update `run_tick()` in `backend/server.py`:
    1. Define configurable constants: `MAX_SCHEDULED_ATTEMPTS = int(os.environ.get("MAX_SCHEDULED_ATTEMPTS", "5"))`, `BACKOFF_BASE_SECONDS = int(os.environ.get("BACKOFF_BASE_SECONDS", "30"))`, and `MAX_BACKOFF_SECONDS = int(os.environ.get("MAX_BACKOFF_SECONDS", "3600"))`.
    2. Define helper function `compute_backoff_seconds(attempt: int) -> int` implementing exponential delay: `min(BACKOFF_BASE_SECONDS * (2 ** max(0, attempt - 1)), MAX_BACKOFF_SECONDS)`.
    3. In `run_tick()`'s exception handler for `_run_scheduled(doc)`:
       - Read `attempts = doc.get("attempts", 0) + 1`.
       - If `attempts < MAX_SCHEDULED_ATTEMPTS`:
         - Calculate `next_run = now() + timedelta(seconds=compute_backoff_seconds(attempts))`.
         - Update document: `{"state": "PENDING", "run_at": next_run.isoformat(), "last_error": str(e)[:500], "failed_at": now_iso()}`.
         - Record audit event on lead: `kind="error"`, `reason=f"scheduled.{doc.get('kind')}_retrying"`, `meta={"attempt": attempts, "next_run_at": next_run.isoformat(), "error": str(e)[:500]}`.
       - If `attempts >= MAX_SCHEDULED_ATTEMPTS`:
         - Update document: `{"state": "DEAD_LETTER", "last_error": str(e)[:500], "failed_at": now_iso(), "dead_letter_reason": f"Exceeded max attempts ({MAX_SCHEDULED_ATTEMPTS})"}`.
         - Record audit event on lead: `kind="error"`, `reason="scheduled.dead_letter"`, `meta={"attempts": attempts, "error": str(e)[:500], "action_id": doc["id"]}`.
    4. Ensure `summary` in `run_tick()` tracks `retried` and `dead_lettered` counts alongside `drained` and `failed`.
  </action>
  <verify>backend/.venv/bin/pytest backend/tests/test_tick.py</verify>
  <acceptance_criteria>
    - Actions failing with `attempts < 5` return to `PENDING` with future `run_at` and incremented `attempts`.
    - Actions failing on attempt 5 transition to `DEAD_LETTER`.
  </acceptance_criteria>
  <done>Scheduled actions withstand transient failures via exponential retries and park permanently broken actions in DEAD_LETTER.</done>
</task>

<task type="auto">
  <name>Task 2: Implement Dead-Letter Queue Inspection and Requeue Endpoints</name>
  <files>backend/server.py</files>
  <read_first>backend/server.py</read_first>
  <action>
    Add administrative DLQ management endpoints in `backend/server.py`:
    1. `GET /api/queue/dead-letter`:
       - Protected with `dependencies=[Depends(require_admin)]`.
       - Queries `db.scheduled_actions.find({"state": "DEAD_LETTER"}).sort("failed_at", -1)`.
       - Returns list of dead-letter actions with `id`, `lead_id`, `kind`, `attempts`, `last_error`, `failed_at`, `dead_letter_reason`, and associated lead info.
    2. `POST /api/queue/dead-letter/{action_id}/retry`:
       - Protected with `dependencies=[Depends(require_admin)]`.
       - Finds the document by `id` in `DEAD_LETTER` state.
       - Updates document: `{"$set": {"state": "PENDING", "run_at": now_iso(), "attempts": 0, "last_error": None, "requeued_at": now_iso()}}`.
       - Records audit event `scheduled.requeued` on lead.
       - Returns `{"status": "requeued", "action_id": action_id}`.
  </action>
  <verify>backend/.venv/bin/pytest backend/tests/test_tick.py</verify>
  <acceptance_criteria>
    - `GET /api/queue/dead-letter` lists quarantined actions.
    - `POST /api/queue/dead-letter/{action_id}/retry` returns action to `PENDING` ready for immediate tick draining.
  </acceptance_criteria>
  <done>Operators can inspect and manually replay dead-lettered queue actions.</done>
</task>
