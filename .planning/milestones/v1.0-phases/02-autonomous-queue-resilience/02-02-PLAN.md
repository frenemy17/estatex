<task type="auto">
  <name>Task 1: Implement MongoDB-Backed Sliding Window Rate Limiter with TTL Index</name>
  <files>backend/server.py</files>
  <read_first>backend/server.py</read_first>
  <action>
    Update rate limiting logic in `backend/server.py`:
    1. Update `rate_limit()` to be asynchronous: `async def rate_limit(request: Request, bucket: str = "lead", per_min: int | None = None) -> None:`.
    2. Check `LEAD_RATE_LIMIT_PER_MIN` (return early if `<= 0`).
    3. Extract client IP: `ip = (request.client.host if request.client else "unknown") or "unknown"`, `key = f"{bucket}:{ip}"`.
    4. Compute window boundary: `window_start = (now() - timedelta(seconds=60)).isoformat()`.
    5. Query `db.rate_limits.count_documents({"key": key, "ts": {"$gte": window_start}})`.
    6. If `count >= limit`: raise `HTTPException(429, f"Rate limit: max {limit} requests/minute")`.
    7. Insert hit document: `await db.rate_limits.insert_one({"key": key, "ts": now_iso(), "expires_at": now() + timedelta(seconds=120)})`.
    8. In `create_lead`, await `rate_limit(request, "lead")`.
    9. On server startup / lifecycle (`lifespan`), ensure TTL index on `db.rate_limits`: `create_index([("expires_at", 1)], expireAfterSeconds=0)` and `create_index([("key", 1), ("ts", 1)])`.
    10. Maintain fallback helper `_in_memory_rate_limit(key, limit)` to guarantee that if Mongo is unreachable or mocked, rate limiting functions without crashing.
  </action>
  <verify>backend/.venv/bin/pytest backend/tests/test_tick.py -k test_lead_capture_is_rate_limited_per_ip</verify>
  <acceptance_criteria>
    - `rate_limit` stores hits in `db.rate_limits`.
    - Subsequent hits exceeding `per_min` within 60s raise HTTP 429.
    - Rate limits persist across in-memory dict clears.
  </acceptance_criteria>
